# Hyprland Configuration

Modular Hyprland configuration written in **Lua**.

> Since Hyprland 0.55, hyprlang (`.conf`) is deprecated in favour of Lua, and new config
> features are no longer added to hyprlang. This config was migrated to `hyprland.lua`.
> `hyprlock` and `hypridle` are separate binaries with no Lua format, so they stay `.conf`.

## Structure

```
~/.config/hypr/
├── hyprland.lua           # Main entry point (requires all config modules)
├── hyprlock.conf          # Lock screen        (hyprlang — separate binary)
├── hyprlock-colors.conf   # Lock screen colors (wallust-generated, gitignored)
├── hypridle.conf          # Idle daemon        (hyprlang — separate binary)
├── .luarc.json            # Points the Lua LSP at /usr/share/hypr/stubs
├── README.md              # This file
│
├── config/                # Modular configuration files
│   ├── lib.lua            # Shared values: mainMod, programs, paths
│   ├── variables.lua      # Environment variables

│   ├── animations.lua     # Animation curves and settings

│   ├── layouts.lua        # Dwindle & Master layout settings
│   ├── autostart.lua      # Startup applications
│   ├── binds.lua          # Keybindings (grouped by function)

└── scripts/               # Custom scripts
    ├── shader-menu.sh             # Rofi menu to pick a screen shader
    │
    ├── power/                     # Power management
    │   ├── hypr-profile.sh        # Apply power/balanced/performance profile
    │   ├── game-mode.sh           # Toggle game mode
    │   ├── profile-menu.sh        # Rofi menu for profiles
    │   ├── powerprofile-status.sh # Status output for waybar

    │

    │   └── hotspot-menu.sh        # Rofi menu: toggle, edit name and password
```

## Quick Reference

### Edit Configuration

| File | Purpose |
|------|---------|
| `lib.lua` | Programs (`terminal`, `menu`), `mainMod`, shared paths |
| `variables.lua` | Environment variables |
| `monitors.lua` | Monitor resolution and positioning |
| `appearance.lua` | Colors, gaps, borders, shadows, blur |
| `animations.lua` | Animation speeds and curves |
| `input.lua` | Keyboard layout, mouse sensitivity, touchpad, gestures |
| `layouts.lua` | Dwindle/Master layout options |
| `autostart.lua` | Programs that start with Hyprland |
| `binds.lua` | All keybindings |
| `rules.lua` | Window rules (float, move, etc.) |

Each `require()` is its own error scope, so a mistake in one module will not stop the
others from loading. If a module fails, Hyprland shows an error popup and provides
emergency binds: **SUPER+Q** (terminal), **SUPER+R** (run), **SUPER+M** (exit).

### External displays

Plug in HDMI (or DisplayPort over USB-C) and it **mirrors** the laptop screen.
That is the catch-all rule at the bottom of `config/monitors.lua`: an empty
`output` matches any monitor without a rule of its own, so it covers whichever
connector is used. Hyprland's own default would have put the display to the
right as a second desktop instead.

`SUPER + CTRL + D` (`scripts/display/display-menu.sh`) changes it: mirror,
extend to the left or right, laptop screen only, or external screen only. Rules
are applied with `hyprctl eval`, since `hyprctl keyword` refuses to work under
the Lua config manager, and every call is checked for an error rather than
failing silently.

**The menu opens with or without a cable attached.** With nothing plugged in
the choice is simply recorded, and the next display to be connected comes up in
that mode. That works because the mode is stored on the *catch-all* rule rather
than under a connector name, so it is not tied to any particular port.

**A choice survives `hyprctl reload` and a reboot.** It is written to
`config/display-mode.lua` (generated, gitignored) and read back by
`config/monitors.lua` -- the same idiom `scripts/shader-menu.sh` uses for
`active-shader.lua`. Delete that file to go back to mirroring. Every degenerate
case falls back to mirroring too: missing, empty, malformed, or a table with no
usable position, all five checked.

Before this it lived only in the compositor's memory, so the `hyprctl reload`
that `scripts/wallpaper/set-wallpaper.sh` ran on every wallpaper change --
including the one `awww-cycle.sh` fires every 200 s -- put an extended display
back to mirroring within three and a half minutes, with nothing to blame but
the wallpaper. That reload is gone; see "Wallpaper and colours".

#### Why "External screen only" is no longer a trap

It switches `eDP-1` off. Unplugging the cable then used to leave **zero enabled
outputs** -- a black screen that only came back when the cable did. Hyprland
0.56 creates a headless placeholder called `FALLBACK` so the session survives,
but headless shows nothing.

Three independent things now prevent that, deliberately, because the first
depends on an event that cannot be verified without real hardware:

1. **`config/monitors.lua` hooks `monitor.removed`** and relights the panel when
   nothing is lit. Pure Lua, no background process. `hl.get_monitors()` returns
   only enabled, non-mirroring monitors, so its length *is* the lit-screen
   count. A `_G` strike counter caps it at three reloads in 30 s -- a reload
   loop would be worse than a dark screen with working keybinds.
2. **`eDP-1`'s rule names `disabled = false`**, which makes `SUPER + SHIFT + R`
   (a plain reload) an unconditional way back. This is the layer that works
   even if the event never fires.
3. **`SUPER + CTRL + D` itself.** With no display attached and the panel off
   there is nowhere to draw a menu, so the script skips it and reloads instead.

All three use a reload rather than an `hl.monitor` eval, and that is not
arbitrary: monitor rules are applied from a `render.preChecks` listener and
`canRender()` is false while a monitor is disabled, so re-enabling a panel
while nothing is rendering can be queued and never applied (upstream discussion
#15437). A config reload is the only path that calls `ensureMonitorStatus()`
synchronously.

The mode is also never persisted for this row: it stores the extend geometry
and applies the panel-off half live only, so a reload or a reboot always comes
back with a lit screen.

#### Two things measured, against expectation

- **A monitor rule merges; it does not replace.** A rule omitting `scale` left
  a monitor at `scale = 2`; a rule omitting `disabled` left one switched off.
  That is why every rule here names every key, and why `eDP-1`'s rule had to
  say `disabled = false` out loud. (A reading of the Hyprland source says the
  opposite -- that `add()` erases the rule and re-parses from defaults. The
  measurement is what this config relies on, and naming every key is correct
  under either.)
- **The menu was never the lag.** The theory was that re-applying `eDP-1`'s
  rule forced a modeset of the panel on every action. Counting
  `Modesetting eDP-1` across a Mirror -> Extend action gives **0 on both the
  old and the new script**. Whole-script time is ~40 ms either way. It now does
  one `hyprctl eval` instead of two (9.2 ms vs 18.8 ms) and one
  `hyprctl monitors all -j` instead of four, which is tidier but not a fix.
  What remains is compositor-side: switching mirroring migrates every workspace
  with an animation each, rebuilds the layout, and updates every window's
  surface scale.

#### Known upstream, not fixable here

`#15695`/`#15698` -- mirroring fails to resolve when the mirror target connects
after the mirroring output, `mirrorOf` stays `"none"` (0.56.1, open).
`#16286` -- mirror to extend needs the monitor off and on again. `#16464` --
VRAM is never freed on monitor disconnect, one buffer per event, still present
in 0.56.2, which matters on 8 GB of shared memory if you replug often.
`SUPER + SHIFT + R` is the documented recovery for all three.

`kanshi`, `shikane` and `way-displays` are deliberately **not** used. Hyprland
does implement `wlr-output-management-unstable-v1`, but on 0.56.x its `test` is
a stub, apply acknowledgements are frame-coupled (`#15525`), and a wlr client's
cached state can shadow config rules indefinitely (open PR `#14343`). In-config
Lua is the right road here and adds no package.

Closing the lid with a display plugged in does **nothing at all** -- not even
lock (`scripts/display/lid-close.sh`). The mirror's source is `eDP-1`, so
locking or powering the laptop panel down would blank the external screen too,
which is exactly when the lid tends to be shut. The panel stays lit inside the
closed lid; that is the trade. Unplug and the usual lock-and-suspend is back.

That script filters out `FALLBACK` as well. Without it, a lid close with no
screen on would have found the placeholder, decided a display was attached, and
done nothing -- leaving the machine awake and unlocked at the worst moment.

### Wallpaper and colours

`scripts/wallpaper/set-wallpaper.sh` runs `wallust`, which regenerates ten
template outputs, then re-applies just the three Hyprland colours it changed
(the two border gradients and the shadow) with one `hyprctl eval` into
`config/theme-colors.lua`.

It used to finish with a blanket `hyprctl reload`. That re-evaluated every
config file to pick up three colours -- and `awww-cycle.sh` calls this script
every 200 s, so it was roughly 430 full config re-evaluations a day, each one
resetting the display mode. A partial `hl.config` was verified to merge rather
than reset siblings, three levels deep: `decoration:shadow:range`, `:rounding`,
`:blur:size` and `:screen_shader` all survive the call untouched.

`config/theme-colors.lua` exists so the colours, their fallbacks and the
gradient angle have one home -- `config/appearance.lua` reads it at config load
and the script reads it after every wallust run, and a second copy in shell
would have drifted the first time one changed.

**One consequence worth knowing:** hand edits to `hypr/config/*.lua` are no
longer picked up for free within 200 seconds. Use `SUPER + SHIFT + R`.

### Power Profiles

Access via `SUPER + SHIFT + G`:

- **Power Saving** — disables animations, blur and shadows, enables VFR
- **Balanced** — normal desktop experience
- **Performance** — max performance for apps

Each of the three confirms itself with a notification carrying its own icon.
`hypr-profile.sh` only ever echoed to stdout, and it runs from rofi and from the
waybar module -- neither has a terminal -- so switching used to give no sign at
all. If `powerprofilesctl` refuses the system profile, the notification says so
rather than claiming a switch that only half happened.
- **Game Mode** — toggles on/off (the waybar icon shows 🎮 while active):
  - `performance` profile. CachyOS's power-profiles-daemon then switches the
    sched-ext scheduler (`scx_lavd`, run from boot by `scx_loader`, installer
    stage 8) into its **Gaming** mode, and back to Auto afterwards.
  - animations, blur and shadows off; `render:direct_scanout = 2` so fullscreen
    games skip compositing
  - notifications on Do Not Disturb; the wallpaper cycle paused so no wallust
    run or `hyprctl reload` hits mid-game
  - the waybar Wi-Fi module paused (zero CPU): it keeps its last icon, and
    "no internet" changes show once Game Mode is turned off
  - Thunar thumbnails off and `tumblerd` killed, so opening a folder of
    screenshots mid-game decodes nothing; the previous setting is restored
    afterwards
  - turning it off restores exactly what was there before, including the
    previous profile. Picking another profile while it's on ends it first.

  `ananicy-cpp` stays on and keeps prioritising game processes. Feral
  gamemode is deliberately not used; the CachyOS wiki says it conflicts with
  ananicy-cpp.

### Gaming with Lutris

Installer stage 9 sets Lutris's global **Command prefix** to CachyOS's
`game-performance` (in `~/.local/share/lutris/system.yml`). Every game then
holds the performance profile, and so scx Gaming mode, and blocks idle and
lock while it runs, with no need to open the menu. Game Mode on top adds the
desktop-side changes above. For Steam, use `game-performance %command%` as a
game's launch option.

## Usage

1. **Edit config files** in `~/.config/hypr/config/`
2. Hyprland reloads the moment you save. To reload manually: `SUPER + SHIFT + R`
   (or `hyprctl reload`)
3. **Check for errors** with `hyprctl configerrors`
4. **Explore the API** with `hyprctl repl` (interactive Lua REPL)

### Changing settings at runtime

`hyprctl keyword` does **not** work under the Lua config manager — it returns
*"keyword can't work with non-legacy parsers. Use eval."* Use `hyprctl eval` instead:

```sh
hyprctl eval 'hl.config({ general = { border_size = 4 } })'
```

A chunk may hold several statements separated by `;`, which is one eval and one
reconfigure rather than two. `config/monitors.lua` relies on this.

Useful pieces of the Lua API, with the signatures measured on 0.56.2 rather
than guessed (the stubs below cover `hl.*`, but these were worth pinning down):

| call | notes |
|---|---|
| `hl.on(event, fn)` | Events include `monitor.added`, `monitor.removed`, `monitor.focused`, `monitor.layout_changed`, `config.reloaded`, `hyprland.start`. A `monitor.*` handler receives one `HL.Monitor`. |
| `hl.get_monitors()` | Returns only **enabled, non-mirroring** monitors, like `hyprctl monitors` rather than `monitors all`. A rule-disabled monitor vanishes from it even with `{ all = true }`. |
| `hl.timer(fn, { type, timeout })` | `type` is `"oneshot"` or `"repeat"`, `timeout` in **milliseconds**. The function comes first. |
| `hl.notification.create({ text, duration })` | Hyprland's own on-screen notification, so unlike `notify-send` it is not suppressed by swaync Do Not Disturb. |

**`hyprctl reload` clears every `hl.on` subscription.** Handlers registered from
a config file therefore do not accumulate across reloads -- they are wiped and
re-registered by the re-evaluation. The practical consequence: never guard a
registration with a flag that outlives the reload, because the Lua state *does*
survive and the flag would permanently block re-registration. A handler
registered with `hyprctl eval` is gone at the next reload for the same reason.

### Editor autocompletion

`.luarc.json` points the Lua LSP at the stubs shipped in `/usr/share/hypr/stubs`,
giving completion and type checking for the whole `hl.*` API.

## Notes

A few things about this setup that are not obvious from the config alone.

**SSH agent.** `SSH_AUTH_SOCK` points at `$XDG_RUNTIME_DIR/gcr/ssh`, served by
`gcr-ssh-agent.socket`. gnome-keyring no longer provides an ssh-agent (50.0
accepts only `--components=pkcs11,secrets`), so the old
`$XDG_RUNTIME_DIR/keyring/ssh` path is dead. If `ssh-add -l` says *Error
connecting to agent*, the socket is not enabled:

```sh
systemctl --user enable --now gcr-ssh-agent.socket
```

Stage 8 of `install.sh` enables this for you, and `./install.sh --check` reports
whether the socket is active.

**Coffee Mode** (the Waybar toggle) stops and restarts `hypridle` rather than
signalling it. hypridle handles neither SIGUSR1 nor SIGUSR2, and the default
disposition of SIGUSR1 is to kill the process -- so signalling it silently
disabled idle locking and idle-suspend until the next login.

**swaync** is started from `autostart.lua`, so `swaync.service` is masked. Left
unmasked, D-Bus tries to activate a second copy at login, fails against the bus
name the first one already holds, and leaves a permanently failed unit. Stage 8
of `install.sh` masks it; `./install.sh --check` warns if it ever comes back
unmasked.

**Notification timeouts live in `swaync/config.json`** (symlinked to
`~/.config/swaync`). Stock swaync ships `timeout-critical: 0`, which means a
critical notification never disappears on its own -- so anything sent with
`notify-send -u critical` sat on screen until clicked. This repo sets 5 s for
normal, 3 s for low and 20 s for critical, and reserves `-u critical` for the
one real emergency, the battery-below-5% warning. An expired notification is
not lost: it stays in the control center (the bell in Waybar). Everything else
falls back to `/etc/xdg/swaync/`. Reload with `swaync-client -R`.

The **look** is generated: `wallust/templates/swaync.css` becomes
`~/.config/swaync/style.css`, so a notification is a card in the wallpaper's
colours with a coloured left edge -- accent normally, a fixed red for critical.
Every `notify-send` in the repo also passes `-i` with a symbolic icon, so Wi-Fi,
hotspot, battery, recording and the rest are told apart at a glance and the icon
picks up the accent colour. `set-wallpaper.sh` reloads it with
`swaync-client -rs`. The icon table is in `swaync/README.md`.

**The login screen is SDDM** running qylock's `pixel-hollowknight` theme --
see `sddm/README.md` for what that involved (qylock is a theme pack, not a
login manager, so SDDM replaced greetd) and for the rollback. Everything below
about noctalia-greeter still applies to that fallback, which stays installed.

**The fallback login screen is greetd + noctalia-greeter** (the CachyOS default). It
guesses 1.5x scale on this panel, so everything on it looked huge; the
resolution was always right. `greetd/greeter.toml` pins `[output] scale = 1.0`,
matching Hyprland. Stage 8 of `install.sh` copies it to
`/var/lib/noctalia-greeter/greeter.toml` (a copy, because the greeter user
cannot read `$HOME`), backing up any existing file. `./install.sh --check`
reads the scale the greeter actually used from this boot's journal.

**Caps Lock and Num Lock popups need a system service.** SwayOSD comes in two
halves: `swayosd-server` (started from `autostart.lua`) only draws the popup,
and `swayosd-libinput-backend.service` is what tells it a lock key was pressed.
The volume and brightness popups work without the backend because those keys are
Hyprland binds calling `swayosd-client` directly; Caps and Num Lock are handled
by the keyboard itself, so the only way to notice them is to read `/dev/input`,
which a user session may not do -- hence a **system** unit, enabled by stage 8 of
`install.sh` (`sudo systemctl enable --now swayosd-libinput-backend.service`).
`./install.sh --check` warns when it is inactive.

**The power menu is Rofi** (`scripts/power/power-menu.sh`), not wlogout. Logout
runs `hyprctl dispatch exit` rather than `loginctl terminate-user`, which polkit
rates `auth_admin_keep` and would demand a password just to log out. Shutdown,
Reboot and Logout ask for confirmation first, because Rofi commits on Enter;
Lock and Suspend do not, being harmless.

**Alt+Tab keeps fullscreen** because of `misc:on_focus_under_fullscreen = 1` in
`appearance.lua`, not because of anything in the bind. That option decides what
happens when a tiled window asks for focus while another is fullscreen, and its
stock value is `2` (`exit_fullscreen`) -- which tore the fullscreen down on
every cycle. `1` (`take_over`) hands the fullscreen to whichever window you
cycle to instead. It applies to every focus change, arrow keys included.

**The two Tab binds are different tools.** `ALT + Tab` cycles within the current
workspace via `cyclenext`. `SUPER + Tab` opens a Rofi list of every window on
every workspace, built from `hyprctl clients` rather than Rofi's own `window`
mode -- that mode works here over wlr-foreign-toplevel, but the protocol carries
no workspace information.

**Hibernate is deliberately absent** from that menu. It cannot resume on this
machine: no `resume=` kernel parameter, no `resume` hook in `mkinitcpio.conf`,
and `/swapfile` (4G) is smaller than RAM (7.4G). Suspend is unaffected and works
normally. Fix the initramfs and swap first, then add the entry back.
